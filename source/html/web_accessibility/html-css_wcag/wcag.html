Web Content Accessibility Guidelines

A comprehensive overview of the POUR framework and compliance levels.

By Pollazzon Manuel 4 min read

WCAG Guidelines and Standards

Web Accessibility Principles (The POUR Framework)

WCAG 2.2 is organized around four foundational principles — Perceivable, Operable, Understandable, Robust — each of which subsumes a set of normative guidelines.

Principle 1 — Perceivable

Information and user interface components must be presentable to users in ways they can perceive.

This includes Text Alternatives to provide alternatives for any non-text content. It also encompasses Time-based Media to provide alternatives for time-based media (captions, audio description). Content must be Adaptable to create content that can be presented in different ways without losing structure, and Distinguishable to make it easier to see and hear content, including separating foreground from background.

Principle 2 — Operable

User interface components and navigation must be operable.

The guidelines require components to be Keyboard Accessible to make all functionality available from a keyboard. Users must have Enough Time to read and use content. It must avoid Seizures and Physical Reactions by not designing content in a way that is known to cause seizures. Content should be Navigable to provide ways to help users navigate, find content, and determine where they are. Finally, it must support Input Modalities to make it easier to operate functionality through various inputs beyond the keyboard.

Principle 3 — Understandable

Information and the operation of the user interface must be understandable.

This requires text content to be Readable and understandable. Web pages must be Predictable and appear and operate in predictable ways. Systems must provide Input Assistance to help users avoid and correct mistakes.

Principle 4 — Robust

Content must be robust enough that it can be interpreted reliably by a wide variety of user agents, including assistive technologies.
Note

Parsing Success Criterion was removed in WCAG 2.2 for being now handled automatically

This means it must be Compatible to maximize compatibility with current and future user agents.

Compliance Levels and Conformance Framework

The Three Conformance Levels

Every success criterion in WCAG 2.2 is assigned one of three levels:

Level A

Minimum baseline. Non-negotiable for any accessible system.

Level AA

Standard target for most legal and procurement frameworks (e.g., EU EN 301 549, US Section 508, ADA-aligned policy).

Level AAA

Enhanced, contextual conformance; not recommended as a blanket site-wide target.

The Five Conformance Requirements

WCAG 2.2 defines five conformance requirements:

First is Conformance Level, meaning to fully satisfy all requirements of the chosen level. Second is Full Pages, meaning conformance applies to full web pages, not fragments. Third is Complete Processes, requiring every step in a multi-step process to conform. Fourth is Only Accessibility-Supported Ways, instructing to use only accessibility-supported technologies. Finally, Non-Interference ensures no content may interfere with the accessibility of other content.
