Screen Magnifiers

Assistive technology that enlarges digital content for users with low vision — and how to build websites that hold up under zoom

By Andrii Synelnyk 5 min read

Who Needs Magnification?

Low vision is one of the most common visual impairments globally. Unlike blindness, low vision cannot be fully corrected with glasses or contact lenses, leaving users with reduced acuity, restricted field of view, or both. Screen magnifiers bridge this gap by enlarging on-screen content so that users can read and interact with it comfortably.

Magnifiers are used by people with conditions such as macular degeneration, glaucoma, diabetic retinopathy, and albinism. They are also widely used by older adults whose visual acuity declines with age. The World Health Organization estimates that at least 2.2 billion people have a vision impairment, of whom approximately 1 billion have moderate or severe impairment that could benefit from magnification aids.

Types of Magnification Tools

Magnification can happen at several layers — hardware, operating system, or browser — and the magnification mode affects what layout problems developers need to address.

Comparison of magnification approaches
Tool / Method Zoom target Examples
OS-level full-screen zoom Entire display macOS Zoom, Windows Magnifier (full screen)
OS-level lens / docked zoom Region near cursor Windows Magnifier (lens mode), ZoomText
Browser zoom Page layout (reflows) Ctrl/Cmd + and -, browser settings
Text-only zoom Font size only Firefox text zoom, OS accessibility font size
Dedicated software Full screen + enhancements ZoomText, SuperNova Magnifier

OS-level magnification captures a bitmap of the screen and enlarges it; the web developer has no direct control over this. Browser zoom, however, triggers a full layout reflow and directly exposes weaknesses in CSS design — making it the most important scenario to design and test for.

WCAG 1.4.4 — Resize Text

WCAG 2.2 Success Criterion 1.4.4 (Level AA) requires that text can be resized up to 200 % without assistive technology and without loss of content or functionality. WCAG 1.4.10 (Reflow, Level AA) further requires that content can be presented at 400 % zoom in a single column without requiring two-dimensional scrolling (except for content that requires it, like data tables or maps).

Quick test

Open your page in Chrome or Firefox, press Ctrl + (or Cmd + on Mac) until the browser zoom reaches 400 %. Does the content reflow into a single column? Can you still reach every piece of content and every interactive control without horizontal scrolling?

Layout Techniques That Support Magnification

Use relative units for text

Set font sizes in rem or em rather than fixed px values. This allows the browser's text-only zoom and OS-level font size preferences to scale typography proportionally, without breaking the surrounding layout. 

/* Good: scales with user preferences */
body { font-size: 1.0625rem; }   /* 17px equivalent */
h2   { font-size: 2rem; }

/*  Bad: ignores user font preferences */
body { font-size: 17px; }
h2   { font-size: 32px; }

Flexible containers with max-width

Use width: 92%; max-width: 72rem; patterns so that content columns narrow at high zoom levels instead of overflowing or requiring horizontal scrolling.

Avoid overflow: hidden on text containers

Clipping overflow on elements that contain text will truncate content at high zoom. Prefer overflow: auto or let containers expand vertically.

Minimum touch / click target sizes

Zoomed interfaces increase the visual size of elements but the browser's internal coordinate system stays the same. This means a 24 x 24 px button remains 24 x 24 CSS pixels at any zoom level. WCAG 2.5.8 recommends a minimum target size of 24 x 24 CSS pixels; aim for 44 x 44 CSS pixels or larger for primary actions.

Sticky and fixed elements

Sticky navigation bars and fixed overlays consume a large fraction of the viewport at high zoom, sometimes leaving almost no space for content. Keep sticky elements as short as possible and test at 400 % zoom on a standard 1 920 px monitor, which simulates a device width of 480 CSS px.

Watch out for horizontal overflow

A single element with a fixed pixel width wider than the viewport at the current zoom level will force a horizontal scrollbar onto the entire page, breaking WCAG 1.4.10. Audit with browser DevTools by toggling the responsive design mode at 320 px wide.

Dedicated Magnification Software Features

Professional magnification software such as ZoomText or SuperNova adds capabilities beyond simple enlargement:

  • Focus tracking: the magnified viewport follows the keyboard focus and text cursor automatically, so users never lose their place.
  • Colour enhancement: adjustable contrast, brightness, and hue can be layered on top of the standard screen rendering.
  • Mouse pointer customisation: oversized, brightly coloured cursors prevent pointer loss in a zoomed viewport.
  • Speech integration: many magnification tools bundle a simplified screen reader for text-to-speech fallback when zooming alone is not sufficient.

Because dedicated software captures a pixel-level bitmap, the main developer responsibility is to ensure the visual presentation itself is high quality — good contrast, clear typography, and unambiguous focus indicators remain visible even at extreme magnification.
