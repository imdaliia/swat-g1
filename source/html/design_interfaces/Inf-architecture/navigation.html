Navigation Design

Where am I, where can I go, and how do I get back? Menus, breadcrumbs and the small details that keep users from getting lost.

Designing interfaces

Navigation is the part of the architecture users actually see and click on. At any moment it should answer three questions: Where am I? Where can I go? How do I get back? If it doesn't, people start pressing the back button a lot.

3.1 Types of navigation

A system usually mixes several types of navigation, each with its own job:

Table 1 - Main types of navigation
TypeWhat it's forExample
GlobalReaching the main sections from anywhereTop menu (Courses, My enrolments, Timetable)
LocalMoving inside the current sectionSidebar with the subject areas of a semester
ContextualLinking related contentPrerequisites written as links
BreadcrumbsShowing where you areHome > Courses > Autumn 2026 > Informatics
SupplementalOther ways to reach contentSitemap, A-Z index, search box

3.2 Common patterns

The most common patterns are the top bar for main sections, the sidebar for sub-sections, the mega menu and, on small screens, the hamburger menu. Hiding the menu saves space, but people tend to forget options they can't see.

Small wayfinding cues help a lot: highlighting the current menu item, page titles that match the clicked link, and a logo that always leads home. Above all, the menu must be consistent: same place, same items, same order on every page.

3.3 Getting back from the wrong path

Users will click the wrong link sometimes. What matters is that fixing it is cheap: the global menu is always there, breadcrumbs take you up one level in one click, and the search box is on every page.
