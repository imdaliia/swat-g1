Prototyping and Usability Evaluation

How can an early representation of an interface help us test and improve a design?

Information System Engineering Part 1 of 3

Why create a prototype?

A prototype is an early representation of an interface. It makes a proposed design concrete enough to examine, discuss and test. Instead of evaluating an idea only from a description, users and designers can look at screens and, in some cases, try a task.

Prototyping supports the design process before implementation. It can reveal whether the planned content and sequence of screens are understandable, and it provides something that can be evaluated with representative users.

Key purpose

A prototype is not the finished system. It is a way to make a design testable, discover problems and guide improvements.

Three useful prototype formats

The level of detail can vary. The topic guide identifies low-fidelity sketches and wireframes, as well as clickable prototypes, as the core formats to consider.

1. Low-fidelity sketches

Sketches are quick, simple representations of possible screens. They are useful for exploring an initial idea or comparing different ways to arrange information before spending time on a more detailed version. Paper prototypes can also be tested with users early in the design process [1].

At this stage, the main concern is the proposed structure and the elements that users will need, rather than polished visual details.

2. Wireframes

Wireframes give a more organized view of a screen. They show where content, controls and navigation elements may appear, helping the team inspect the page structure and the relationship between its parts.

A wireframe can make it easier to discuss whether the information needed for a task is present and arranged in a useful order.

3. Clickable prototypes

A clickable prototype connects screens or interface elements so that a person can move through a proposed flow. It can represent the main steps of a task without requiring the complete information system to be implemented.

This format is useful when the team needs to observe how a user moves from one step to another, where the user expects to go next, and whether the task flow is understandable. The level of fidelity should match what the team wants to learn from the test [2].

Comparing the three formats
Format What it represents Useful when
Sketch A quick outline of a possible screen Exploring an early idea or layout
Wireframe The structure and arrangement of page elements Reviewing content hierarchy and screen organization
Clickable prototype A connected sequence of screens or actions Trying a realistic task flow before implementation

Example: prototyping course registration

Consider a university course-registration system. A student needs to find a course, check its prerequisites, understand whether places are available and complete enrolment. A prototype can represent the screens and steps needed for this task.

  1. Sketch: outline the course list, course details and enrolment screens.
  2. Wireframe: organize the course information, prerequisites, available places and main controls on each screen.
  3. Clickable prototype: connect the screens so a user can attempt the route from finding a course to confirming enrolment.

The example shows how a design can become more concrete while remaining a prototype. The next step is to ask representative users to attempt realistic tasks with it.

Prepare a prototype for evaluation

A prototype should contain the parts of the interface needed for the task being examined. Before a test, make sure that the relevant screens and the intended route can be explored by the participant. The prototype does not need to represent every feature of the final system; it needs to make the selected task testable.

Keep the test focused

Choose a task first, then prepare the screens and interactions needed for a user to attempt it.
