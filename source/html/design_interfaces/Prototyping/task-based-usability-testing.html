Task-Based Usability Testing

How can we observe whether representative users can complete realistic tasks?

Information System Engineering Part 2 of 3

What is task-based usability testing?

Task-based usability testing evaluates a proposed interface by asking people to attempt tasks that reflect real goals. The focus is on what happens while users try to complete those tasks, not only on whether the design looks clear to its creators.

A test can use a prototype, including a clickable prototype, so that the design can be examined before the complete system is implemented. Observing task attempts helps identify where the interface supports users and where problems arise. Tests are most useful when tasks are believable and relevant to the people taking part [1].

Choose representative test users

Participants should be representative of the people for whom the information system is intended. Their goals and context of use should be relevant to the tasks being tested. This helps the team understand how the proposed interface works for its intended users.

Why this matters

A test based only on the designer's own opinion cannot show how other intended users will approach the same task.

Prepare realistic tasks

A test task should describe something a user needs to accomplish in the system. It should reflect a real goal rather than simply asking a participant to inspect an isolated interface element. The selected tasks should match the purpose of the test and the parts of the prototype that are ready to explore.

Example: a course-registration task

Imagine testing a prototype for university course registration. A realistic task could ask a student to find a course, check its prerequisites, understand whether places are available and complete enrolment.

Example task sequence
  1. Find a course that the student wants to take.
  2. Open the course details and check the prerequisites.
  3. Check whether places are available.
  4. Complete the enrolment process in the prototype.

This sequence gives the participant a meaningful goal and gives the observer a clear process to examine from beginning to end.

Observe how users attempt the tasks

During a task, observe the participant's progress through the interface. Record whether the task is completed, where the participant encounters difficulty, whether errors occur and whether help is needed. These observations help explain the results collected during evaluation. Recording clear observations makes it easier to analyse a session and identify useful findings [2].

What to observe during a task
Observation Question to consider
Task progress Can the participant move through the required steps?
Difficulties At which point does the participant hesitate or become unable to continue?
Errors Does the participant make an error while trying to complete the task?
Help Does the participant need assistance to proceed?
Completion Is the intended task completed?

A practical testing sequence

  1. Set the purpose: decide which part of the interface or task flow needs to be evaluated.
  2. Prepare the prototype: make sure the screens and interactions needed for the task can be explored.
  3. Prepare realistic tasks: use tasks that reflect the goals of the intended users.
  4. Invite representative users: involve people whose context is relevant to the system.
  5. Observe and record: note completion, difficulties, errors and help required.
  6. Review the findings: use the observations to decide what should be examined or changed in the next iteration.
Keep the focus on the user

The purpose is to learn how people use the proposed interface, not to test whether participants can guess what the designer intended.
