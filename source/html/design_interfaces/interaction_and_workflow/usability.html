Usability

Can people achieve their goals with the product, quickly, correctly and without frustration? Components, heuristics and methods to find out.

Designing interfaces Usability Evaluation

1. What is usability?

Usability is the degree to which a product can be used by specific people to achieve specific goals effectively, efficiently and with satisfaction in a specified context of use. This is the wording adopted by the ISO 9241-11 standard, and every word in it matters.

  • Effectiveness: can users complete the task correctly and completely?
  • Efficiency: how much time, effort and attention does it cost them?
  • Satisfaction: how comfortable and acceptable is the experience?
  • Context of use: who the users are, what they want to do, with which equipment and in which environment.

The last point is the one most often forgotten. Usability is not a property that an interface simply has: it emerges from the relationship between a particular interface, a particular user, a particular task and a particular setting. A ticket machine that is perfectly usable for a commuter who knows the system can be unusable for a tourist in a hurry, with a suitcase, in a language they do not speak.

Key idea Never ask “is this interface usable?” in the abstract. Ask “usable by whom, for what, and where?”.

This first article covers usability: its components, the heuristics used to inspect interfaces, and the methods used to measure it. The second article widens the view to the whole user experience.

2. The five components of usability

Jakob Nielsen breaks usability down into five quality components. They are useful as a checklist, because different products need to prioritise them differently.

Learnability

How easily can first-time users accomplish basic tasks? Essential for public kiosks, websites and anything used rarely.

Efficiency

Once users have learned the system, how quickly can they perform tasks? Essential for professional tools used for hours every day.

Memorability

When users return after a period of not using it, can they re-establish proficiency without learning everything again?

Errors

How many errors do users make, how severe are they, and how easily can they recover? Critical in medical, financial and industrial systems.

Satisfaction

How pleasant is the system to use? Satisfaction is subjective but measurable, and it strongly affects whether people keep using a product.

Components can conflict. Features that make a tool fast for experts (shortcuts, dense screens, abbreviations) can hurt learnability for beginners. Good design does not maximise every component: it chooses a balance based on the real users and their tasks, and often provides layers so that beginners and experts are both served.

3. Nielsen’s ten usability heuristics

Heuristics are broad rules of thumb, not step-by-step recipes. The ten below, formulated in the 1990s and refined since, remain the most widely used framework for inspecting an interface.

The ten usability heuristics
Heuristic What it asks for Typical violation
1. Visibility of system status Keep users informed about what is happening, through timely feedback A form that submits with no progress indicator or confirmation
2. Match between system and the real world Use the user’s language and concepts, not internal jargon Error messages showing database codes
3. User control and freedom Provide clearly marked exits, undo and redo A wizard that cannot go back without losing all data
4. Consistency and standards Follow platform and industry conventions; same words mean the same thing “Save”, “Submit” and “Done” used for the same action in different screens
5. Error prevention Eliminate error-prone conditions or ask for confirmation before commitment A “Delete account” button placed right beside “Save”
6. Recognition rather than recall Make options and information visible instead of requiring memory Asking users to remember a code from a previous page
7. Flexibility and efficiency of use Offer accelerators such as shortcuts, defaults and customisation for experts No keyboard shortcuts in a tool used all day
8. Aesthetic and minimalist design Show only relevant information; every extra element competes with the useful ones A dashboard where ten widgets have equal weight
9. Help users recognise, diagnose and recover from errors Explain the problem in plain language and suggest a constructive solution “Invalid input” without saying which field or why
10. Help and documentation Provide short, searchable, task-oriented help when it is needed A 200-page manual with no search

4. Heuristic evaluation

A heuristic evaluation is an inspection method in which a few evaluators examine an interface and judge it against a set of heuristics. It is cheap, fast and can be done on early prototypes, which makes it a good first filter before testing with real users.

  1. Prepare. Define the scope, the user profile and the key tasks to examine.
  2. Evaluate individually. Several evaluators (typically three to five) go through the interface independently, at least twice: once to get a feel for the flow, once to look at each element.
  3. Record problems. Each issue is described, located and linked to the heuristic it violates.
  4. Rate severity. Evaluators score how serious each problem is.
  5. Consolidate. Findings are merged, duplicates removed and fixes prioritised.

Working independently matters: one evaluator finds only a fraction of the problems, and the combined list from several people is far more complete. Severity is usually rated on a scale like this:

  • 1 Cosmetic: fix only if time allows.
  • 2 Minor: low priority, but worth fixing.
  • 3 Major: important to fix, high priority.
  • 4 Catastrophe: must be fixed before release.
Limitation Heuristic evaluation relies on expert judgement. It finds many real problems but also flags some that users would never meet, and it can miss problems that only show up when real people attempt real tasks. It complements usability testing; it does not replace it.

5. Usability testing and metrics

In a usability test, representative users attempt realistic tasks with the product while observers watch, listen and take notes. In the popular think-aloud protocol, participants verbalise what they are looking at, expecting and feeling, which exposes the reasoning behind their mistakes. Tests can be moderated or unmoderated, in a lab or remote, on a rough prototype or on a finished product.

Frequently used usability metrics
Metric What is measured Relates to
Task success rate Percentage of participants who complete a task correctly Effectiveness
Time on task How long a task takes, usually for successful attempts only Efficiency
Error rate Number and severity of mistakes per task Errors, effectiveness
Questionnaire scores Self-reported ease and satisfaction, e.g. SUS Satisfaction

The System Usability Scale (SUS)

SUS is a ten-question questionnaire answered on a five-point agreement scale. Odd-numbered items are positively worded and even-numbered items negatively worded, which is why the scoring inverts them:

For odd items  (1, 3, 5, 7, 9):   contribution = answer - 1
For even items (2, 4, 6, 8, 10):  contribution = 5 - answer

SUS score = (sum of the ten contributions) × 2.5        → a value between 0 and 100

A score around 68 is commonly cited as average, but SUS is not a percentage: it is best used to compare versions of the same product or a product against its competitors.

How many participants? As a rule of thumb, a small group of about five users from one user type uncovers a large share of the major problems, so several small, iterative rounds are usually more valuable than one big test. Distinct user groups, or quantitative metrics that need statistical confidence, require more participants.
